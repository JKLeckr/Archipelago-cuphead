It is a requirement by the Archipelago community to disclose LLM AI usage. This file is used to disclose usage.

I use the term LLM to describe a specific type of AI model that was used during development. There are plenty of other types of AI that aren't as notorious or controversial as LLMs.

This project has gone through several iterations of LLM touching. The majority of "AI assisted" code has been replaced with simpler human-designed code (those versions never got released anyways). The original code is NOT LLM-touched, but some of the newer code has fragments of LLM-touched code. While I mainly work on this APWorld by hand now, it does not deny that LLMs were used on this project a good amount at some point during later developement. The specific case is during the rewrite of the logic system from alpha02 to alpha03. Previous (failed, and ultimately scrapped) iterations were heavily LLM-involved (and that mess still exists in the git history during early alpha03 development). After scrapping those systems, I, myself, have designed and written this new system (with inspiration from certain parts of the scrapped code).

A good amount of places in the code had been LLM-touched at some point when diagnosing a problem. Certain parts like items and locations were renumbered and reorganized using an LLM.

Some specific things to note:

- Unit Tests: Most were hand coded, but some of the more newer ones were written by an LLM.
- Tool Scripts: Most of these are assisted by LLM (meaning, the LLM suggests the code or example, and I implement it). I thoroughly test it and ensure it passes the strict type checker and linter and is maintainable. The only tool that is not LLM-assisted is gencs_apobject, which was originally a Jupyter Notebook project adapted into script form. Some of the parts of the other LLM-assisted scripts like the module importing was the inspiration for implementing the module importing into the gensc_apobject script.
- levelrules: This had a history of LLM involvement in the past during development of the new system (alpha03). The new system was written by me, but were inspired by the original mess code to some degree. I would consider this "AI assisted" in a technical sense. I did have LLM assistence with migrating the rules from the previous failed system to the new system that is currently used. I combed through and cleaned and rewrote and fixed every rule to ensure there aren't logic issues associated with the migration (LLMs are definately not perfect at getting things perfect). I work on the rules and the system by hand these days and I understand the system well as I designed it and wrote most of it.

- The docs are completely handwritten (and I complain about writing documentation a lot). I prefer my style of writing than the LLM's, so I never use AI to write the documentation. Also, writing my own documentation proves I know how my project works.

- Art and Creative assets are NOT and NEVER will be generated by LLMs. I am strict with this.

While there are parts of the project that are "AI touched", I primarily work on this project by hand. There may be contributions in the future that may have involved LLMs in the future (though, I dislike slop very much, I am not anti-AI). I will note those cases here if there are LLM involved contributions.

I take pride in my work, and I am very picky about code quality, so I make sure the code I push out is something I can be happy with.
